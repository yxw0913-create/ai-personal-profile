## 二、结合版架构（四层）

```
L4 智慧层   后台综合＋主动关联：夜间提炼、对齐综合、重大决策前自动调历史
L3 核心层   MEMORY.md 精炼版（全量注入每次会话）＋登记表（按需调取）
L2 结构层   决策登记表 / 事件登记表 / 人物档 / 项目档（结构化、低冗余）
L1 原始层   对话原文、每日日志、照片与小票、业务文件（只增不改，可溯源）
```

- **唯一事实源原则**：同一事实只在一个地方记全量，其余地方只留指针（见 3.3）。
- **双引擎分工**：日常采集、结构化、检索、判断由 Muse 实时完成；批量苦力（历史回填、全量重整）派给 DeepSeek Harness 按你的分级规则跑。

## 三、强压缩方案（本方案的核心）

目标口径：原始对话约 100 万 token 的信息量，核心层常驻不超过约 1 万 token，**压缩约 100 倍**，且关键语义无损。靠三招：

### 3.1 决策一行化（压缩比最大的一招）

一次决策的来回讨论动辄上万 token，但决策本身只需要一行：

```
日期 | 决策 | 依据（一句） | 状态 | 取代了哪条
2026-11-07 | 熔断线定为人工复核触发线 | 回测证机械执行更差 | 生效 | 取代「-20%自动执行」设想
```

登记表预计常驻规模：一年约 300–500 行，约 2–3 万字，随查随取，不全量注入。

### 3.2 摘要金字塔（时间维度压缩）

```
当日对话/日志（原始，L1）
  → 日结：当日事实与决定，约 20 行（写入每日日志尾）
    → 周结：并入周复盘/周小结，只留结论与变化
      → 核心层：只有改变长期状态的，才进 MEMORY.md
```

规则：越往上越只留「变化量」——没变的事实不重复叙述，只留指针。

### 3.4 断舍离原则（2026-11-08 用户补充并定案）

记忆是 Agent 与大模型之间的纽带和基础，活跃层必须像断舍离一样**强行淘汰垃圾信息（约 80–90%）**：闲聊、过程性往返、已失效的中间稿、无结论的试探，不进入结构层和核心层。与 3.3 的调和口径：**断舍离作用于活跃层（L2–L4）；原始层（L1）冷存归档、不进日常调用，只供溯源**——丢的是调用权重，不是证据本身。

### 3.3 压缩三原则（防压坏）

1. **只压叙述，不压数字与原话**：金额、日期、比例、用户原话的关键表述，逐字保留。
2. **每条压缩必可溯源**：登记表与摘要都标注来源（日期＋文件），查得到原文才敢压。
3. **被推翻的只标状态、不删除**：旧决定标「已被 XX 取代」，留痕一行——防止旧结论日后被当成现行规则捞回来。

## 四、写入规范（RULE v2，沿用你的编号并修订）

| 规则 | 触发条件 | 写入位置 |
|---|---|---|
| R1 | 每日收尾（或当日最后一次对话后） | 每日日志＋日结段 |
| R2 | 决策/判断/选择成立 | 决策登记表＋（重大者）MEMORY.md |
| R3 | 用户明确偏好或纠正 | MEMORY.md 偏好区＋PROACTIVE_PREFERENCES |
| R4 | 项目关键节点、数额变化 | 项目档/业务台账（如财务总账、协作总册） |
| R5 | 技能/流程被验证有效或修正 | 技能库/作战手册修订 |
| **R6（新增）** | **重大决策或花钱之前** | **先检索决策登记表与相关档案，把历史依据摊出来再决定** |
