# 异步协同与夜间运行机制 v0.1

> 状态：2026-11-10 用户点选四题（1A/2A/3B/4A）后转正，全文并入《记忆运行规范 v1.2》第四节正式生效；本文件保留为沿革稿。其中第 3 题用户选 B「报告随到随报」，取代本草案原「待批队列上限 7」的口径。（草案）

> 起因：2026-11-08 深夜用户提出——用户睡觉/不在线时，AI 体系不应停摆；但也不能靠海量 token 硬撑。成果如何投递才不浪费用户注意力，与「机器不闲着」是同一个问题的两面。
> 定位：本草案把已有机制（定时任务、主动投递偏好、宪章的无回复默认、作战手册的待批队列）统一成一套口径，待用户确认后并入运行规范。

## 一、问题拆解

1. **回合制损耗**：传统对话是「说一句答一句」，用户不在，系统就停；且长对话记忆漂移会出现「说了白说、记混」。
2. **注意力损耗**：成果若随到随推，用户休息时被打扰、碎片时间被垃圾信息占用；若不推，用户又不知道发生了什么。
3. **成本损耗**：让大模型 24 小时空转思考，token 成本不可控，且多数产出是低价值的。

## 二、解法四件套（行业通行方向＋我们的实现）

### 1. 定时驱动（钟表层）
固定节律的活交给日程：已在运行——08:18 量化晨报、09:00 待办清单、周五 11:00 建议书、周日 20:00 复盘、21:00 健康小结、后台夜间记忆综合。用户睡觉时跑的全是**已授权的确定性任务**，不临场发明新任务。

### 2. 事件驱动（触发层）
没有事件就零成本待机；事件到达才唤醒处理（如风险巡逻命中、价格触线、对方回复到达）。原则：**监控用脚本不用模型**——脚本巡逻近乎免费，命中才叫醒模型。

### 3. 分级唤醒（成本层）
沿用 DeepSeek 分级思想到整个体系：
- 巡逻级（脚本/小模型）：盯盘、盯邮箱外的一切信号源、格式整理——成本≈0；
- 整理级（Flash 级）：攒批消化日志、回填登记表、起草待批件；
- 决策级（Muse 总控/Pro 级）：只在需要判断时介入，产出一页结论。
**贵的脑子只在决策点开机，便宜的眼睛全天睁着。**

### 4. 攒批投递（注意力层）
产出不直达用户，先进**待批队列**，按三条车道分流：
- **S 车道**：重要且紧急——即时推送全渠道（宪章既有规则）；
- **A 车道**：重要不紧急——攒到约定节点批量呈报（早 09:00 清单、晚间批量、周五/周日节点）；
- **B 车道**：只归档可查——进文件和登记表，用户想看时一句话调出。
队列上限沿用作战手册：同时待批 ≤7 件，超了先清队列再进新件。用户无回复时按宪章执行最稳妥默认，绝不自作主张推进不可逆动作。

## 三、防「说了白说」机制

指令不再只活在对话里：成立即落登记表/规范/台账（今晚已立）。任何一线 agent 开工前先读同一事实源，口径冲突以登记表＋最新用户确认为准。对话可以压缩、可以遗忘，**登记在册的状态不会漂移**。

## 四、成本护栏

- 每个定时/后台任务设 token 预算上限，超限即停并报告，不许静默烧钱；
- 每周日在全流程复盘里加一行「本周后台运行成本」速览（先人工口径，跑顺了再自动化）；
- 夜间只跑钟表层和触发层；需要大模型长考的新课题，一律攒到用户在场或攒成批处理包派给 Harness，不夜间单开。

## 五、今晚的结论（草案口径）

「不闲着」≠「不停烧」：覆盖不留空窗靠的是钟表＋触发，产出不浪费注意力靠的是攒批＋分道，指令不丢失靠的是登记制。三者合起来，就是这台机器在用户睡觉时的样子：**眼睛睁着，手在干活，嘴等节点。**
